# 나라입찰

브라우저에서 4명이 함께 하는 가격 퀴즈·입찰 경쟁 게임 프로토타입입니다.
`nara_quiz_dev_spec.pdf` v0.1의 대기실 → 카탈로그 → 10라운드 → 최종 순위를 구현했습니다.
React + TypeScript + Vite 화면, Node.js + Socket.IO 서버를 한 프로젝트에서 관리합니다.
실행 의존성은 React, React DOM, Socket.IO 서버/클라이언트 4개이며, 상태 관리·CSS·HTTP 서버는 기본 기능을 사용합니다.

## 공개 게임 주소

**[https://nara-auction.onrender.com](https://nara-auction.onrender.com)**

위 주소를 친구 3명에게 공유하세요. 각자 닉네임을 입력하고, 한 명이 방을 만든 뒤 나머지는 같은 방 코드로 참가합니다.
참가자에게 설치나 계정 가입은 필요 없습니다. Render의 `My Workspace`에서 싱가포르 지역 무료 서버 1대로 실행 중입니다.

## 인터넷에 공개하기 (GitHub → Render)

[Render에서 이 저장소 배포하기](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fk56754665%2Fnara-auction)

1. 위 링크를 열고 Render에 로그인합니다. GitHub 계정으로 가입·로그인할 수 있습니다.
2. 이 저장소 접근을 요청하면 허용합니다. 비공개 저장소라면 Render의 GitHub 연동에 이 저장소를 지정하세요.
3. Blueprint 설정을 확인하고 배포합니다. 루트의 `render.yaml`에 무료 웹 서비스, 빌드·실행 명령, 상태 확인 경로가 준비되어 있습니다.
4. 배포 상태가 **Live**가 되면 Render가 실제로 발급한 `https://…onrender.com` 주소를 엽니다. 아직 배포하지 않았다면 이 주소는 생성되지 않습니다.
5. **게임 주소를 친구들에게 공유**합니다. 모두 같은 주소에서 닉네임을 입력하고 같은 방 코드를 사용하면 서로 다른 장소·네트워크에서도 같은 방에 참가할 수 있습니다. 친구들은 Node.js 설치나 GitHub·Render 로그인 없이 플레이합니다.

GitHub 저장소 주소는 소스 코드 주소입니다. GitHub Pages는 정적 화면 호스팅이므로 이 게임의 Node.js·Socket.IO 서버를 실행할 수 없습니다.
Render가 화면과 서버를 **같은 공개 HTTPS 주소**로 제공합니다. 사용자 PC를 켜 둘 필요가 없고 프론트엔드 서버 주소를 따로 설정하지 않아도 됩니다.

현재 설정은 무료 인스턴스 **1대**입니다. 방이 서버 메모리에 있으므로 인스턴스 수를 늘리거나 여러 서버로 나누면 안 됩니다.
무료 서비스는 15분 동안 트래픽이 없으면 쉬며, 다시 접속할 때 약 1분 걸릴 수 있습니다. 절전·서버 재시작·재배포 시 이전 경기는 사라집니다.
개발 중에는 **On Commit 자동 배포**를 사용합니다. 이 저장소의 GitHub `main` 브랜치에 push하면 Render가 자동으로 `npm ci --include=dev` → `npm test` → `npm run build`를 실행하고, 모두 성공하면 같은 게임 주소에 새 버전을 반영합니다.
Render의 GitHub 앱은 `k56754665/nara-auction` 저장소 하나에만 연결했습니다.
사이트 반영 기준은 GitHub `main`으로 push한 커밋입니다. [Render 관리 화면](https://dashboard.render.com/web/srv-dbqvfrmk1f9s73ariki0)에서 배포가 **Live**가 되면 새로고침해 확인하세요. 테스트나 빌드가 실패하면 이전에 성공한 버전이 유지됩니다.
**자동 배포로 서버가 재시작되면 진행 중인 방과 경기는 초기화됩니다.**

이 설정은 무료 플랜을 선택합니다. Render에서 별도로 유료 플랜으로 바꾸거나 추가 유료 자원을 만들 필요가 없습니다.
실제 공개 배포 완료 여부와 공개 링크는 Render의 배포 결과로 확인해야 합니다. 설정 파일이나 GitHub push만으로 배포 완료를 의미하지 않습니다.

참고: [GitHub Pages 설명](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Render 배포 버튼](https://render.com/docs/deploy-to-render), [무료 서비스 제한](https://render.com/docs/free).

## 1. 내 컴퓨터에서 바로 실행하기 (Windows)

1. Node.js 22.12 이상을 설치합니다. 이 프로젝트를 검증한 버전은 22.20.0입니다.
2. 이 폴더에서 PowerShell 또는 터미널을 열고 아래 명령을 순서대로 실행합니다.

```powershell
cd C:\OtherProject\nara-auction
npm install
npm run dev
```

3. 실행 중인 터미널을 그대로 두고 브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.
4. 닉네임을 입력하고 **새 방 만들기**를 누릅니다. 표시된 6자리 방 코드를 전달합니다.
5. 다른 참가자 3명은 같은 주소를 열고 각자의 닉네임과 방 코드를 입력해 **코드로 참가**합니다.
6. **방장을 포함한 4명 모두 준비 완료**를 누른 뒤, 방장이 **4인 경기 시작**을 누릅니다.
7. 카탈로그를 읽고 모두 **열람 완료**를 누르면 시작합니다. 최대 열람 시간은 15분입니다.
8. 라운드 결과에서 모두 다음 라운드 준비를 누르거나 마감을 기다립니다. 10라운드 후 최종 순위가 나옵니다.

방 코드 아래에는 **방 닫고 메인으로**(방장) 또는 **메인으로 나가기**(일반 참가자) 버튼이 있습니다.
방장이 확인창에서 방 닫기를 누르면 경기 도중에도 방과 기록이 삭제되고 모든 참가자가 메인으로 돌아갑니다.
일반 참가자가 대기실에서 나가면 새 사람이 빈 좌석으로 참가할 수 있습니다. 경기 중 나가면 이미 확정한 입찰·정산은 유지되며 이후 차례는 시간 초과로 처리됩니다.
나가기·방 종료 후에는 토큰이 삭제되므로 새로고침으로 이전 자리나 종료된 방이 복원되지 않습니다.

한 컴퓨터에서 시험하려면 **새 탭을 4개 열어 주소를 직접 입력**하세요. 각 탭을 독립된 참가자로 사용할 수 있습니다.
브라우저의 '탭 복제'는 sessionStorage까지 복제하므로 같은 참가자로 인식할 수 있습니다.
같은 토큰으로 다시 연결하면 마지막 연결이 자리를 제어하고 이전 연결은 종료됩니다.

다른 컴퓨터에서 접속할 때는 같은 네트워크에서 서버 컴퓨터의 IPv4 주소를 사용합니다.
예: `http://192.168.0.10:3000` (실제 서버 IP로 바꿔 입력).
서버는 `0.0.0.0`으로 열립니다. Windows 방화벽이 연결을 차단한다면 Node.js의 개인 네트워크 접근을 허용해야 합니다.
실제 다른 기기에서의 로컬 네트워크 접속은 이 환경에서 검증하지 않았습니다. 공개 인터넷 주소는 위 Render 링크를 사용하세요.

종료는 터미널에서 `Ctrl+C`를 누릅니다. 3000번 포트가 사용 중이라면 다음과 같이 바꿀 수 있습니다.

```powershell
$env:PORT = '3001'
npm run dev
```

그때는 `http://localhost:3001`에 접속하세요.

## 2. 게임 규칙

- 초기 운영자금은 업체당 **3,000만 원**, 카탈로그 **30종**, 공고 **10건**입니다.
- 공고 예산 합계는 **2억 원**, 각 예산은 **500만 원 이상**입니다. 9·10라운드 원가는 각각 3,200만·3,400만 원으로 앞선 수익이 필요합니다.
- 가격 퀴즈는 단위당 정수 원으로 한 번 제출합니다. 절대 오차가 기준 단가의 **±10% 이내**면 자격을 얻습니다. 경계값을 포함합니다.
- 첫 입찰은 비공개이며 **원가 이상, 예산 이하, 10만 원 배수**여야 합니다. 운영자금은 `max(원가, 심사 실패 비용)` 이상이어야 합니다.
- 첫 입찰 마감 후 최저가와 유효 입찰을 공개합니다. 좌석 순으로 한 번씩 재입찰하며, 호출 시점의 1위는 자동으로 건너뜁니다. **최저가보다 최소 10만 원** 낮게 제출해야 합니다. 포기·시간 초과는 기존 가격을 유지합니다.
- 동일한 최종 입찰가는 가격 퀴즈의 절대 오차가 작은 업체를 우선합니다. 오차도 같으면 라운드 시작 시 미리 정해 공개한 서버 추첨 순서를 따릅니다.
- 1순위는 바로 규격 퀴즈에 들어갑니다. 후순위는 도전·포기를 선택합니다. 선택 시간 초과는 비용 없이 포기합니다.
- 정답이면 **자신의 최종 입찰가**로 계약하고 `계약가 - 납품원가`를 자금에 더하며 납품 실적을 1건 올립니다.
- 오답·답안 시간 초과는 **예산의 5%를 원 단위로 내림**하여 차감합니다. 다음 후보가 도전하고, 모두 실패·포기하면 유찰됩니다. 앞선 차감은 유지됩니다.
- 가격 답안·입찰 미제출은 참여 포기입니다. 전원 자격 미획득·미입찰이면 비용 없이 유찰됩니다.
- 최종 우승자는 **납품 1건 이상인 업체 중 운영자금 최다 업체**입니다. 최고 자금이 같으면 공동 우승, 자격을 충족한 업체가 없으면 우승자 없음입니다.
- 최종 순위 표시는 납품 실적이 있는 업체를 먼저 자금순으로, 실적 없는 업체는 그 뒤에 자금순으로 나열합니다. 같은 자금·같은 자격은 같은 순위입니다.

## 3. 시간·테스트 데이터 바꾸기

`server/config.ts`의 `DURATIONS`를 수정하세요. 단위는 밀리초(1초 = 1,000)입니다.

| 단계 | 기본 시간 | 시간 초과 처리 |
| --- | --- | --- |
| 카탈로그 | 15분 | 첫 공고로 이동 |
| 입찰 공고 | 10초 | 가격 퀴즈 시작 |
| 가격 퀴즈 | 30초 | 미제출 자격 없음 |
| 첫 입찰 | 30초 | 미제출 입찰 포기 |
| 재입찰 | 업체당 15초 | 기존 입찰가 유지 |
| 후순위 심사 선택 | 업체당 10초 | 비용 없이 포기 |
| 규격 답안 | 업체당 20초 | 5% 비용 차감 |
| 라운드 결과 | 15초 | 다음 공고 또는 최종 순위 |

카탈로그와 결과 단계는 전원이 확인하면 일찍 끝납니다. 다른 단계도 해당 참가자들의 제출이 끝나면 즉시 진행합니다.
연결이 끊겨도 서버의 시간은 계속 흐릅니다. 브라우저의 카운트다운은 표시용이며 서버가 실제 마감을 판단합니다.
코드 수정으로 개발 서버가 재시작되면 경기도 초기화되므로 경기 시작 전에 설정하세요.

물품과 문제는 `server/data.ts`의 `CATALOG`, `TENDERS`를 교체합니다.
공고에는 물품 ID, 기관, 수량, 예산, 기준 단가, 필수 규격, 문제·보기·정답 ID가 들어갑니다.
기본 데이터는 30종 중 정해진 10종을 순서대로 출제하는 가상 데이터입니다. 첫 공고는 PDF의 노트북 예시입니다.
시작 시 양의 정수 단가·수량, 카탈로그와 단가 일치, 유효 입찰가 존재, ID·정답, 30종·10건·예산 합계를 검사합니다.

## 4. 프로젝트 구조

```text
src/
  App.tsx            단계별 화면, 입력, 결과와 기록
  connection.ts     단일 Socket.IO 연결·이벤트 구독·토큰·요청 처리
  style.css         일반 CSS와 모바일 대응
shared/
  protocol.ts       클라이언트/서버 공통 메시지와 공개 상태 타입
server/
  index.ts          실행 진입점
  app.ts            기본 HTTP 서버, 개발 시 Vite, Socket.IO 연결
  game.ts           방, 단계, 마감, 제출, 재접속, 정산
  rules.ts          자격·입찰 검증·실패 비용·최종 순위 계산
  config.ts         게임 규칙 상수와 단계별 시간
  data.ts           교체 가능한 서버 전용 콘텐츠
tests/
  lobby.test.ts     실제 4개 연결의 대기실 검증
  room-exit.test.ts 방 종료 권한, 전원 통지, 나가기와 빈 좌석 재사용
  round.test.ts     PDF 예시와 경계값
  timeouts.test.ts  마감, 포기, 유찰, 재접속, 자동 타이머
  match.test.ts     실제 4개 연결의 10라운드·재전송 검증
  browser-smoke.ts  독립된 브라우저 4세션의 전체 경기
  room-exit-browser.ts 브라우저 4세션의 방 종료·나가기·새 방 생성
```

서버가 모든 단계·순위·자금·납품 건수를 결정합니다. 클라이언트에는 참가자별로 만든 공개 상태만 보냅니다.
첫 입찰 마감 전에는 타인의 입찰가를 포함하지 않고, 본인의 제출가와 제출 여부만 복원할 수 있습니다.
토큰은 서버가 난수로 발급하며 다른 참가자에게 보내지 않습니다.
제출은 `phaseId + requestId`로 검사합니다. 같은 요청의 재전송은 성공 응답만 반복하고, 다른 요청 ID로 중복 제출하거나 과거 단계의 답안을 보내면 거절합니다.
규격 정답·실패 처리는 서버 내부에서만 실행하므로 클라이언트가 정산을 요청하는 API는 없습니다.

## 5. 검사와 빌드

```powershell
npm test
npm run typecheck
npm run build
npm run test:browser
npm run test:browser:exit
npm start
```

`npm start`는 개발 도구 없이 빌드된 화면과 서버를 같은 `http://localhost:3000`에서 실행합니다.
브라우저 테스트는 먼저 `npm run build`를 완료해야 하며 기본적으로 설치된 Google Chrome을 사용합니다.
Edge를 사용하려면 다음과 같이 실행하세요.

```powershell
$env:PW_CHANNEL = 'msedge'
npm run test:browser
```

테스트는 별도의 임시 포트에서 실행되고 종료되므로 실제 3000번 포트의 게임에 영향을 주지 않습니다.
화면 테스트 PNG는 `tmp/browser/`에 생성합니다. 긴 제한시간을 기다리지 않도록 테스트에만 주입한 서버 시계를 전진시키며, 실제 서버 자동 타이머도 별도로 검사합니다.

공개 서버도 직접 검증할 수 있습니다. 아래 명령은 별도의 검증용 방을 만들고, 독립된 WSS 연결 4개로 서버의 실제 제한시간을 따라 전체 10라운드를 진행합니다. 약 2분 정도 걸립니다.

```powershell
npm run test:live -- https://nara-auction.onrender.com
npm run test:browser:exit -- https://nara-auction.onrender.com
```

## 7. 현재 제한

- **서버 재시작 시 모든 방·경기·참가자 토큰이 초기화됩니다.** DB·파일 저장 기능은 없습니다.
- 참가자 토큰은 탭의 `sessionStorage`에 보관합니다. 같은 탭의 새로고침·일시적인 통신 단절에는 복원되지만, 탭을 닫거나 저장소를 지우면 같은 자리 복원이 보장되지 않습니다.
- 경기 중 이탈자의 자리는 유지되며 제한시간은 계속 흐릅니다. 대기실에서는 일반 참가자가 직접 나가 자리를 비울 수 있고, 방장은 언제든 방 전체를 닫을 수 있습니다. 방장 교체·경기 중 대체 참가·개별 강제 퇴장·경기 일시정지는 없습니다.
- 방 정리, 계정 로그인, 다중 서버, 관전, 채팅, 부하 테스트는 포함하지 않습니다. 단일 Node.js 프로세스에서 소규모로 플레이하는 프로토타입입니다. 공개 서버는 HTTPS와 WSS로 접속합니다.
- 물품·문제는 가상의 테스트 콘텐츠입니다. 실서비스용 콘텐츠 정확성이나 4인 경쟁의 밸런스는 검증하지 않았습니다.
- `npm run dev`는 개발 서버입니다. 다른 사람에게 빌드를 제공할 때는 `npm run build` 후 `npm start`를 사용하세요.

구현 API는 [Socket.IO 서버 문서](https://socket.io/docs/v4/server-api/)와 [Vite 시작 문서](https://vite.dev/guide/)를 참고했습니다.
